# CLAUDE.md — 친구야 와이어프레임 협업 가이드

이 저장소는 프로젝트 **친구야**(여행 대여 예약 온라인 서비스)의 와이어프레임과 그 상세 설명 문서를 담는다. 이 파일은 여러 직원과 각자의 Claude가 **같은 규칙으로 협업**하도록 하는 지침이다. 작업 시작 전 반드시 이 파일과 `docs/README.md`를 읽는다.

## 저장소 구조

```
chinguya-wireframes/
├─ CLAUDE.md                          # (이 파일) 협업 가이드
├─ 고객페이지_와이어프레임_모바일.html      # 고객(C) 화면 · 모바일
├─ 관리자_와이어프레임_모바일.html         # 관리자(A) 화면 · 모바일
├─ 여행사_와이어프레임_데스크톱.html        # 여행사(G) 화면 · 데스크톱
└─ docs/
   ├─ README.md                       # 문서 인덱스 · 서비스 개요 · 공통 규칙
   ├─ 고객페이지_상세설명.md
   ├─ 관리자_상세설명.md
   └─ 여행사_상세설명.md
```

각 HTML 파일과 `docs/`의 상세 설명 문서는 **1:1로 대응**한다.

## 와이어프레임 작성 규약

- 각 화면은 `<div class="screen" id="...">` 블록 하나로 구성한다.
- 화면 블록에는 반드시 다음이 포함된다:
  - `.cap` — 화면 코드(`.id`, 예: `S1-C2`) · 화면명(`.nm`) · 짧은 설명(`.dsc`).
  - 프레임(`.phone` 모바일 / `.win` 데스크톱) 안의 화면 목업.
  - `.desc` — **화면 상세 정의**: `목적 / 진입 / 주요 요소 / 규칙·로직 / 화면 이동` 5개 항목(`<dl>`).
- 주석 색상 규약: 🟧 주황(`.note`) = 규칙·로직, 🟦 파랑(`.note.blue`) = 확정 대기·연동 메모.
- 상단 `<nav class="index">`의 앵커 링크는 각 화면의 `id`와 일치해야 한다.
- 저채도·저충실도 유지(색·폰트·이미지는 디자인 단계에서 확정). 목적은 **구조·흐름 검토**다.

## ★ 핵심 규칙: 와이어프레임 ↔ 상세 설명 문서 동기화

**와이어프레임 HTML을 수정할 때마다, 대응하는 `docs/*_상세설명.md`를 같은 작업(같은 커밋) 안에서 반드시 함께 수정한다.** 문서 없이 HTML만 바꾸거나 그 반대는 허용하지 않는다.

변경 유형별 처리:

- **화면 추가**: HTML에 `.screen` 블록 추가 → 해당 문서의 **ID 매핑표**에 행 추가 + 화면 상세 섹션(5개 항목) 추가. `nav.index` 앵커도 추가.
- **화면 삭제**: HTML 블록 제거 → 문서의 매핑표 행·상세 섹션·앵커 제거. 이 화면을 참조하던 **다른 화면의 '화면 이동'** 항목도 수정.
- **화면 수정**(요소·규칙·이동 변경): HTML의 `.desc` 내용과 문서의 해당 항목을 **동일하게** 갱신.
- **ID/화면 코드 변경**: HTML `id`·`.cap .id`, `nav.index` 앵커, 문서 매핑표, 그리고 이를 참조하는 모든 교차 링크를 함께 변경.
- **공통 비즈니스 규칙 변경**(재고 산식·예약 기간·상태 흐름 등): 여러 화면에 영향을 주므로 `docs/README.md`의 '공통 비즈니스 규칙'과 관련된 **모든 화면 설명**을 함께 수정.

작업 마무리 전 자가 점검:

1. HTML의 `id`·화면 코드 목록과 문서 매핑표가 일치하는가?
2. `.desc`의 5개 항목과 문서 서술이 어긋나지 않는가?
3. '화면 이동'에서 참조하는 대상 화면이 실제로 존재하는가(깨진 참조 없음)?
4. 교차 파일 참조(예: 관리자 `a-agencyadd` ↔ 여행사 `g-invite`)가 양쪽에 반영됐는가?
5. 공통 규칙을 바꿨다면 영향받는 모든 화면과 `docs/README.md`를 갱신했는가?

## 문서 서술 스타일

- 화면 설명은 항상 `목적 / 진입 / 주요 요소 / 규칙·로직 / 화면 이동` 순서·표현을 유지한다(HTML `.desc`와 대응).
- 화면을 지칭할 때는 `id`와 화면 코드를 함께 쓴다. 예: "`booking`(S1-C2)".
- 반복되는 규칙은 각 화면에 중복 서술하되, 값·정책이 바뀌면 `docs/README.md` 공통 규칙을 **단일 출처(source of truth)**로 삼아 함께 갱신한다.
- 언어는 한국어. 실제 문구·수치는 예시값일 수 있으므로 확정 여부를 파랑 주석으로 표시.

## 화면 코드 체계 (참고)

- 접두어: `C` = 고객, `A` = 관리자, `G` = 여행사.
- 앞 숫자(S0/S1/S2/S3/S4)는 기능군: S0 계정, S1 예약·운영 핵심, S2 여행사·할당·정산, S3 상품, S4 콘텐츠·지원.
- 하나의 `id`가 복수 화면 코드를 겸할 수 있다(예: 관리자 `a-resdetail` = S1-A7/A8). 매핑표를 기준으로 삼는다.
