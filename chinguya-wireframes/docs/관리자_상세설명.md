# 친구야 — 관리자 페이지 와이어프레임 상세 설명

- **대상 파일**: `../관리자_와이어프레임_모바일.html`
- **플랫폼**: 모바일 (저채도 · v1)
- **성격**: 접객 중 현장에서 쓰는 운영 화면. **일반 관리자는 조회 전용**, 쓰기는 **슈퍼어드민**. 22개 관리자 기능을 17개 대표 화면으로 정리.
- **문서 목적**: 각 화면의 `id`(HTML 앵커)와 화면 코드(예: S1-A3)별 기능·규칙·화면 이동을 정의해, 다른 협업자(및 그 Claude)가 와이어프레임을 정확히 이해·수정할 수 있도록 한다.

> **주석 범례**: 🟧 규칙·로직, 🟦 확정 대기·연동, 토글=ON/OFF, 빗금=이미지, 회색 라인=텍스트 자리.

## `a-login` · S0-A2 — 관리자 로그인

- **목적**: 관리자 **아이디/비밀번호 로그인**.
- **진입**: 관리자 앱 실행 시 첫 화면.
- **주요 요소**: 아이디·비밀번호 입력, 로그인 CTA.
- **규칙·로직**: 최초 구동 시 **슈퍼어드민 생성(S0-A1)** 1회 후 잠금, 이후 이 로그인 사용.
- **화면 이동**: 로그인 성공 → 대시보드(`a-dash`).

## `a-dash` · S1-A1 — 대시보드

- **목적**: 운영 현황과 **오늘 방문 예약**을 한눈에 파악.
- **진입**: 로그인 직후, 하단 탭 '홈'.
- **주요 요소**: 지표 카드(신규 예약/입금확인 요청/취소요청), **재고 초과 알림 줄**, 오늘 방문 예약 목록, 하단 탭.
- **규칙·로직**:
  - '오늘 방문 예약' = 오늘 날짜 이용 건(일본 기준 '오늘').
  - **재고 초과 알림** = 그 날짜의 예약 수가 총 보유를 넘은 날. `a-inv`(S1-A3)에서 재고를 예약 수보다 낮게 내렸을 때 발생하며, **해소될 때까지 상시 노출**한다.
- **화면 이동**: 예약 카드 → 예약 상세, 지표 → 해당 목록, **재고 초과 알림 → `a-inv`(S1-A3)의 해당 날짜**.

## `a-asset` · S1-A2 — 자산 관리

- **목적**: 대여 자산(자전거·낚싯대)의 **명칭 마스터** 관리.
- **진입**: 메뉴 → 자산 관리.
- **주요 요소**: 자산 카드(명칭 · 수정/삭제), + 등록 버튼, 목록 하단의 **삭제된 자산 영역**('삭제됨' 뱃지 · 복원).
- **모달 4종**: `A2-M1` 자산 등록 / `A2-M2` 자산 수정 / `A2-M3` 자산 삭제(재고 레코드 유무로 CASE 1·2 문구 분기) / `A2-M4` 자산 복원. 모두 별도 화면 코드를 갖지 않는 `a-asset` 내부 요소다.
- **규칙·로직**:
  - 자산은 **명칭만** 보유한다. **수량은 관리하지 않으며 전부 `a-inv`(S1-A3)에서 기준 보유량과 날짜별 재고 조정으로 관리**한다.
  - 입력 항목이 명칭 하나뿐이므로 **등록·수정·삭제·복원은 별도 화면 없이 모달**로 처리한다.
  - **등록 모달**: 명칭 입력 1개(필수, 앞뒤 공백 제거). 중복 검사는 **활성 자산끼리만** 수행.
  - **수정 모달**: 기존 명칭 프리필. 값 변경이 없으면 저장 비활성. **삭제됨 상태의 자산은 수정 불가**.
  - **삭제 모달**: 해당 자산의 **날짜별 재고 레코드가 0건이면 완전 삭제(hard)**, **1건 이상이면 소프트 삭제**. 문구도 두 경우로 분기한다.
  - 소프트 삭제된 자산은 **목록 하단에 모아 '삭제됨' 뱃지와 함께 계속 노출**한다(활성 자산이 위, 삭제된 자산이 아래).
  - 삭제된 자산은 **복원** 가능하며, 과거 재고·예약 이력을 그대로 승계한다. 복원 시 같은 명칭의 **활성 자산이 이미 있으면 복원 모달에서 명칭 변경을 요구**한다.
  - 삭제된 자산의 명칭은 **새 자산에 재사용 가능**하다(같은 이름이 목록에 둘 보일 수 있으며, 하나는 '삭제됨').
  - 사유(수리/입고/외부임대)는 관리하지 않는다.
  - 등록·수정·삭제·복원은 **슈퍼어드민만** 실행할 수 있다(일반 관리자는 조회 전용).
- **화면 이동**: + 등록 → 등록 모달, 카드 → 수정 모달, 카드의 삭제 → 삭제 확인 모달, 삭제된 카드의 복원 → 복원 모달. **모달만 사용하므로 화면 전환은 없다.**

## `a-inv` · S1-A3 — 날짜별 재고 세팅

- **목적**: 자산별 **기준 보유량**과 **날짜별 재고 조정·매장 휴무**를 달력 뷰로 관리.
- **진입**: 메뉴 → 재고 세팅. 대시보드(`a-dash`·S1-A1)의 **재고 초과 알림**에서도 해당 날짜로 진입.
- **주요 요소**: **자산 선택**(상품 아님), 기준 보유량 카드(값 · 변경 버튼), 달력(잔여/고객 가용 · 여유/임박/마감/초과/휴무 · 재고 조정이 걸린 날 점 표시), 선택일 상세(기준 보유량 · **이 날 조정 N줄** · 그날 총 보유 · 예약 · 잔여 · 매장 휴무 토글), 재고 조정 추가·저장 버튼.
- **모달 3종**: `A3-M1` 기준 보유량 변경 / `A3-M2` 재고 조정 / `A3-M3` 초과 경고. 모두 별도 화면 코드를 갖지 않는 `a-inv` 내부 요소다.
- **규칙·로직**:
  - **수량은 이 화면이 단일 소관**이다. 자산(`a-asset`·S1-A2)은 명칭만 가지므로, 세팅 단위는 **`자산 × 날짜`**다(상품 아님).
  - **기준 보유량**: 자산마다 1개 값으로, "지금 우리가 가진 대수"를 뜻한다. 달력의 각 날짜는 **이 값을 상속**하고, 예외인 날만 **재고 조정** 레코드로 저장한다. 기준값이 있으므로 **매일 손으로 세팅할 필요가 없다.**
  - **변동의 두 경로** — 성격에 따라 입력구가 갈린다.
    - **영구 변화**(자산 추가 구매 · 완전 파손 처분) → **A3-M1 기준 보유량 변경**. `현재값(읽기 전용) → 변경 후 값` 2필드와 **적용 시작일**, 메모로 구성한다. 시작일 **이후** 날짜의 상속값이 한 번에 바뀌며, **과거 날짜와 이미 걸린 재고 조정은 건드리지 않는다**(조정은 새 기준값 위에 그대로 합산).
    - **일시 변화**(펑크·수리 · 주말 임시 임차) → **A3-M2 재고 조정**. `±N` · **기간**(하루짜리는 시작일 = 종료일, 수리처럼 복귀일을 모르면 **종료일 미정**으로 열어두고 복귀 시 종료 처리) · **요일 지정**(예: 7~8월 토·일 +3) · **자유 메모 1줄**로 구성한다.
  - **합산 규칙**: **그날 총 보유 = 기준 보유량 + 그날 걸린 모든 재고 조정의 합**. 한 날짜에 조정이 **여러 개 겹칠 수 있으며**(예: 임차 +3과 수리 −2가 같은 토요일에), 선택일 상세는 조정을 **줄마다 나열**하고 **각각 개별로 수정·해제**할 수 있다. 해제하면 그 조정분만 빠진다.
  - 조정 줄 앞의 태그(임차·수리 등)는 **메모 앞머리를 표시한 것**이며 별도 코드값이 아니다(사유는 자유 메모 1줄로만 관리).
  - **달력 셀 숫자 = `잔여 / 고객 가용`**(예: `4/6` = 6대 중 4대 남음). **색상은 잔여 기준**으로 여유/임박/마감(0)/초과를 구분하고, 재고 조정이 걸린 날은 **우상단 점**으로 표시한다.
  - **Slice 1은 여행사 할당 = 0으로 저장**하므로 **고객 가용 = 그날 총 보유**이고, 관리자는 숫자를 하나만 다룬다. 고객 가용을 따로 입력하는 줄은 두지 않는다.
  - **Slice 2**부터 선택일 상세에 **여행사 할당** 줄이 추가되고 **총 보유 − 여행사 할당 = 고객 가용**으로 자동 계산된다. Slice 1부터 할당을 0으로 채워 두므로 **스키마 변경 없이 승계**된다. (Slice 2 과제: 기준 보유량을 낮췄을 때 **할당분이 총 보유를 넘어서는 경우**의 방어 규칙.)
  - **휴무/블랙아웃은 매장 전역 플래그**다. 전 자산 공통으로 걸리며, 수량 값은 **보존한 채 판매만 차단**한다. 특정 자산 하나만 못 쓰는 날은 휴무가 아니라 **재고 조정으로 수량 0**을 만들어 표현한다.
  - **초과 허용**: 재고를 낮춰 **그날 예약 수보다 총 보유가 작아지면** `A3-M3` 경고를 띄우되 **저장은 허용**한다(실제 파손·수리는 사실이므로). 저장하면 그 날짜에 **'초과' 표시**가 붙고 **대시보드(S1-A1) 알림**에 남는다. 고객앱은 이미 0이라 **신규 예약은 유입되지 않으며**, 관리자가 개별 연락·취소로 해소한다. 기간을 걸친 조정이면 **초과가 생기는 날짜를 모두 나열**한다.
  - **소프트 삭제된 자산**(`a-asset`)은 삭제 시점 **이후 날짜의 기준 보유량 상속을 중단(0)**하고, 과거 날짜의 값과 예약 이력은 그대로 보존한다. **조회만 가능하며 신규 세팅은 불가**하다.
  - 기준 보유량 변경·재고 조정·휴무 설정은 **슈퍼어드민만** 실행할 수 있다(일반 관리자는 조회 전용).
- **화면 이동**: 자산 선택 → 해당 자산 달력, 날짜 탭 → 하단 상세, 기준 보유량 '변경' → `A3-M1`, '재고 조정 추가' 및 조정 줄의 '수정' → `A3-M2`, 저장 시 초과 발생 → `A3-M3`. **모달만 사용하므로 화면 전환은 없다.**

## `a-prod` · S1-A4 — 상품 관리 목록

- **목적**: 상품 목록 조회 및 **표출 ON/OFF** 관리.
- **진입**: 메뉴 → 상품 관리, 하단 탭 '상품'.
- **주요 요소**: 상품 카드(명칭·옵션·표출 토글), + 등록 버튼.
- **규칙·로직**: 상품별 **고객앱 / 여행사앱 표출**을 각각 토글.
- **화면 이동**: + 등록/카드 → 상품 등록·수정(`a-prodedit`).

## `a-prodedit` · S1-A5 — 상품 등록/수정

- **목적**: 상품의 **가격·표출·설명·이미지** 등록/수정.
- **진입**: 상품 관리 목록의 + 등록/카드.
- **주요 요소**: 고객가·여행사가, 고객앱·여행사앱 표출 토글, 타지역 반납 추가요금, 상세 설명, 이미지.
- **규칙·로직**: 여행사가 컬럼은 항상 보유(**고객앱 미노출**), 타지역 반납 추가요금은 **전기 2일 상품에만**.
- **화면 이동**: 저장 → 상품 관리 목록.

## `a-res` · S1-A6 — 예약 관리 목록

- **목적**: 전체 예약을 **상태별**로 조회·검색.
- **진입**: 메뉴 → 예약 관리, 대시보드 지표.
- **주요 요소**: 상태 탭, 검색(예약번호·여권명), 예약 카드(예약번호 + **대표 상품명·'외 N건'**, 상태 태그, **부분취소 뱃지**).
- **규칙·로직**: 필터 **접수/완료/미입금/취소요청/취소**, 목록·검색·페이지네이션. 한 예약에 **복수 항목**이 담기므로 카드는 **대표 상품명 + '외 N건'**으로 표기하고, **부분취소는 별도 탭·상태값 없이 뱃지**로만 노출.
- **화면 이동**: 예약 카드 → 예약 상세·입금확인(`a-resdetail`).

## `a-resdetail` · S1-A7/A8 — 예약 상세 · 입금확인

- **목적**: 예약 상세 확인 및 **입금 확인 → 완료 처리**.
- **진입**: 예약 관리 목록의 예약 카드.
- **주요 요소**: 예약번호·고객·여권명, **예약 항목 리스트**(상품·옵션, 이용일·수량, 금액, 항목 상태), 입금액(유효 항목 합계), 완료 처리 CTA, 미입금 강제 취소.
- **규칙·로직**:
  - **1 예약번호 = N 항목**(항목마다 상품·옵션·이용일이 다를 수 있음), **입금액은 유효 항목 합계** 기준.
  - 입금 확인 시 상태 **완료**, 접수 후 **24시간 내 미입금** 시 '미입금' 표시 → 강제 취소(재고 즉시 복원). 강제 취소는 **예약 전체 단위**(입금 전이므로 부분취소 없음).
  - 일부 항목만 취소된 예약은 **별도 상태값 없이 '부분취소' 뱃지**로 표시하고, 예약 상태는 **유효 항목 기준**으로 유지.
- **화면 이동**: 완료 처리/강제 취소 → 예약 관리 목록 상태 반영.

## `a-cancel` · S1-A9 — 취소요청 처리

- **목적**: 고객 **취소요청**을 **항목 단위**로 검토해 환불·취소 확정.
- **진입**: 예약 관리(취소요청 탭)의 예약 카드.
- **주요 요소**: 예약번호, **취소 요청 항목 리스트**(항목별 이용일·수량·금액·수수료율, 유지 항목은 흐리게), 요청 항목 결제액·**수수료 합산**·환불 예정액·고객 환불계좌, 취소 확정 CTA.
- **규칙·로직**:
  - 수수료는 **항목별 이용일 기준 차등**으로 각각 산정 후 **합산**(한 예약 안에서도 항목마다 요율이 다르다).
  - 환불 이체는 **수동**, 이체 후 '취소' 처리 → **해당 항목·날짜의 재고만** 즉시 복원.
  - **부분취소**면 남은 유효 항목은 유지하고 예약에 **'부분취소' 뱃지**를 붙인다(별도 상태값 없음). **전체 항목** 요청이면 예약 상태를 **취소**로 전이.
- **화면 이동**: 취소 확정 → 예약 상태 반영(전체: 취소 / 부분: 유효 항목 기준 유지 + 부분취소 뱃지).

## `a-set` · S1-A10 — 계좌 · 정책 설정

- **목적**: **입금 계좌**와 **차등 취소 수수료 정책** 설정.
- **진입**: 메뉴 → 계좌·정책.
- **주요 요소**: 입금 계좌(한국 1건), 이용일 기준 구간별 수수료율(예: D-7 이전 0%, D-3~D-6 20%, D-1~D-2 50%), 저장.
- **규칙·로직**: 구간·요율 **수치는 관리자 편집**, 여행사 취소 마감 기준일도 여기서 **유연 조정**(기본 D-3).
- **화면 이동**: 저장 → 정책 반영(취소 계산에 적용).

## `a-admins` · S0-A5/A6 — 관리자 관리

- **목적**: 관리자 계정 **등급 관리**(슈퍼어드민/일반).
- **진입**: 메뉴 → 관리자 관리(슈퍼어드민 전용).
- **주요 요소**: 관리자 카드(아이디·등급 태그), + 추가 버튼.
- **규칙·로직**: 일반 관리자는 **조회 전용**(접객용), 추가/수정/처리·설정은 **슈퍼어드민만**.
- **화면 이동**: + 추가/카드 → 관리자 등록·수정.

## `a-agency` · S2-A1/A3 — 여행사 관리

- **목적**: 여행사 계정 목록 관리 및 **사용 가능/불가** 토글.
- **진입**: 메뉴 → 여행사 관리.
- **주요 요소**: 여행사 카드(명칭·사용 토글), + 등록 버튼.
- **규칙·로직**: 토글 = 사용 가능/불가, 담당자 변경은 상세에서, **불가 시 로그인·예약 차단**.
- **화면 이동**: + 등록 → 여행사 등록(`a-agencyadd`), 카드 → 상세.

## `a-agencyadd` · S2-A2 — 여행사 등록(초대)

- **목적**: 여행사 **초대 이메일 발송**으로 계정 등록 유도.
- **진입**: 여행사 관리의 + 등록.
- **주요 요소**: 여행사명·담당자 이메일 입력, 가입 링크 발송 CTA.
- **규칙·로직**: 담당자가 링크로 **아이디·비밀번호 직접 등록**, 링크 **유효기간 1주일**, 이미 계정 있으면 발송 생략.
- **화면 이동**: 발송 → 여행사 관리 목록.
- **연동**: 여행사 측 계정 등록 화면은 여행사 파일 `g-invite`(S2-G1/G2).

## `a-alloc` · S2-A4 — 날짜별 할당 세팅

- **목적**: 여행사별·날짜별 **재고 할당 수량** 세팅.
- **진입**: 메뉴 → 할당 세팅.
- **주요 요소**: 여행사·**자산**·날짜 선택, 수량 스테퍼, 저장.
- **규칙·로직**: 할당 단위 = **자산 × 날짜별 수량**(`a-inv`·S1-A3와 동일 단위), **총 보유 − 할당 = 고객 가용**(자동). 총 보유는 S1-A3의 **기준 보유량 + 재고 조정** 결과값이며, **할당 합계가 총 보유를 넘지 않도록 방어**해야 한다(기준 보유량을 낮춘 경우 포함). 여행사 예약기간 **+3일 ~ +3개월**.
- **화면 이동**: 저장 → 재고 세팅·여행사 예약에 반영.

## `a-invoice` · S2-A5 — 인보이스 목록

- **목적**: 여행사 **월별 인보이스**를 목록으로 조회.
- **진입**: 메뉴 → 인보이스.
- **주요 요소**: **여행사 필터**, 인보이스 카드(월 · 발행일 · 금액 · **입금 완료/미완료** 태그).
- **규칙·로직**: 여행사마다 **매월 1일 전월 예약 기준** 자동 발행(**수동 등록 없음**), 발행예정(아직 1일 미도래) 건은 발행일·입금상태 표시 없음, 통화 **KRW**(세금 라인 없음), 정산은 **수동 확인**.
- **화면 이동**: 카드 → 인보이스 상세(`a-invoicedetail` S2-A6).

## `a-invoicedetail` · S2-A6 — 인보이스 상세

- **목적**: 인보이스의 **예약 내역 확인**과 **입금(정산) 수동 확인**.
- **진입**: 인보이스 목록(`a-invoice` S2-A5)에서 카드 클릭.
- **주요 요소**: 여행사·대상월·발행일, 전월 **완료·취소 예약 라인**(예약번호·상품·수량·금액·상태), **합계(정산 반영액)**, **입금 확인** CTA.
- **규칙·로직**: 합계 = **완료 예약 금액 합 + 취소 예약의 취소 수수료 합**(취소는 예약 금액이 아닌 **취소 수수료만** 반영), 취소 수수료는 **이용일 기준 차등**, '입금 확인'은 **인보이스 1건 단위**·발행됨·입금 **미완료**일 때만 노출, 누르면 컨펌 **'입금을 확인했습니까?'** → 확인 시 입금 상태 **완료** 전이·목록 반영.
- **화면 이동**: 입금 확인 → 인보이스 목록(S2-A5) 입금 상태 반영.

## `a-qna` · S4-A2 — 문의 관리

- **목적**: 고객 1:1 문의 확인 및 **답변 등록**.
- **진입**: 메뉴 → 문의 관리, 대시보드/알림.
- **주요 요소**: 문의 본문, 답변 입력, 답변 등록 CTA.
- **규칙·로직**: 답변 등록 시 고객에게 **카카오 알림톡** 발송(알림 인터페이스, 실발송 이연).
- **화면 이동**: 답변 등록 → 문의 목록(답변완료).

## `a-cms` · S4-A1/A3 — FAQ · 콘텐츠 관리 (CMS-lite)

- **목적**: **FAQ·랜딩·서비스 소개** 콘텐츠 편집.
- **진입**: 메뉴 → FAQ·콘텐츠.
- **주요 요소**: FAQ 항목(순서 드래그), + FAQ 버튼, 랜딩·소개 콘텐츠 편집 영역.
- **규칙·로직**: FAQ 등록/수정/삭제·**노출 순서** 관리, **분류·검색 없음**, 랜딩/소개 텍스트·이미지 편집.
- **화면 이동**: 편집 → 고객 FAQ·랜딩·서비스 소개(`s4-c2` 등)에 반영.
