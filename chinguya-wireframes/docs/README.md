# 친구야 — 와이어프레임 상세 설명 (문서 인덱스)

이 폴더는 프로젝트 **친구야**(여행 관련 대여 예약 온라인 서비스)의 와이어프레임 HTML 3종에 대한 **화면 ID별 상세 기능 설명**을 담는다. 다른 협업자와 그 Claude가 와이어프레임을 정확히 이해하고 수정할 수 있도록 하는 것이 목적이다.

각 문서는 화면마다 다음 5개 항목으로 기술한다: **목적 · 진입 · 주요 요소 · 규칙·로직 · 화면 이동**. HTML의 `id` 앵커와 화면 코드(S1-C2 등)를 함께 표기한다.

## 서비스 개요

세 개의 사용자군이 하나의 재고 풀을 공유한다.

- **고객(C)**: 모바일 앱. 상품 조회 → 예약 → 무통장 입금 → 관리자 수동 확인 → 완료. 취소는 요청 방식(차등 수수료).
- **관리자(A)**: 모바일 앱. 현장 접객·운영. 자산/재고/상품/예약/취소/여행사/인보이스/콘텐츠 관리. 일반 관리자는 조회 전용, 쓰기는 슈퍼어드민.
- **여행사(G)**: 데스크톱. 할당받은 재고 범위 내 예약(즉시 완료)·즉시 취소·월별 인보이스 정산.

## 공통 비즈니스 규칙 (문서 간 일관성 기준)

이 규칙들은 여러 화면에 걸쳐 반복되므로, 하나를 수정하면 관련 화면 설명을 모두 함께 고쳐야 한다.

- **자산과 수량의 분리**: 자산(S1-A2)은 **명칭·카테고리만** 관리하고, **수량은 전부 날짜별 재고 세팅(S1-A3)** 에서 관리한다. 재고가 붙는 단위는 **`자산 × 날짜`**(상품 아님).
- **상품 ↔ 자산 연결**: 상품은 **자산 1개 + 대여 옵션 1개**로 만든다(자산 1개에 상품 여러 개, 예: 전기 자전거 → 1일·2일·야간).
  - 같은 자산 × 같은 옵션의 활성 상품은 **1개만**. 연결 자산·옵션은 **상품 등록 때만 선택**하고 이후 바꿀 수 없다(S1-A5).
  - 상품을 예약하면 **연결 자산의 재고**를 쓴다. 같은 자산의 상품끼리 재고·여행사 할당을 함께 사용한다.
  - 고객앱은 **자산 1개 = 상품 카드 1개**로 묶고, 그 자산의 '표출 ON' 상품을 **옵션 칩**으로 보여준다(S1-C1·S3-C1).
  - **연결 상품(삭제되지 않은)이 있는 자산은 삭제할 수 없다**(S1-A2). 상품 삭제는 소프트 삭제(S1-A5).
- **자산 카테고리**: 자산은 **자전거 / 낚싯대** 중 1개 카테고리를 가진다(고정값, 코드의 `ProductCategory`·`AssetCategory`와 같음). **등록 때만 선택**하고 바꿀 수 없다. 상품은 연결 자산의 카테고리를 따른다.
  - 옵션: 자전거 = 2시간/1일/2일/야간, 낚싯대 = 1일/2일.
  - 타지역 반납: **2일 상품**만(자전거·낚싯대 모두). 추가요금은 **대당** 부과(추가요금 × 수량). 반납이 하루 늦어지므로 **반납 다음 날(시작일 +2)까지 같은 수량을 점유**한다 — '익일·익익일 자동 마감'의 구현(2026-09-14 확정).
  - 고객 예약은 옵션과 무관하게 **하루 단위**로 재고를 점유한다(2시간도 그날 하루, 2일 = 이틀). **야간**은 운영일을 따로 두지 않고 재고가 있는 날이면 모두 예약 가능하다(2026-09-14 확정).
  - 고객앱 카테고리 칩(S1-C1)과 관리자 상품 목록 탭(S1-A4)은 자산 카테고리 기준.
- **기준 보유량 + 재고 조정**: 자산마다 **기준 보유량** 1개 값("지금 가진 대수")을 두고, 날짜별 값은 **이 값을 상속**한다. 예외는 **재고 조정** 레코드로만 건다. 매일 손으로 세팅하지 않는다.
  - **영구 변화**(추가 구매·완전 파손 처분) → **기준 보유량 변경 + 적용 시작일**(A3-M1). 시작일 이후 상속값이 일괄 변경되고, 과거 날짜와 기존 재고 조정은 보존된다.
  - **일시 변화**(펑크·수리, 주말 임시 임차) → **재고 조정 ±N**(A3-M2). 기간(하루는 시작=종료, 수리는 **종료일 미정** 가능), **요일 지정**(예: 토·일 +3), **자유 메모 1줄**.
  - **그날 총 보유 = 기준 보유량 + 그날 걸린 모든 조정의 합**. 한 날짜에 조정이 **여러 개 겹칠 수 있고 전부 합산**되며, 조정은 **개별 수정·해제** 가능.
- **재고 산식**: `총 보유 − 여행사 할당 = 고객 가용`(0 미만 불가). 여행사가 없거나 할당이 없으면 `고객 가용 = 총 보유`이고 관리자는 숫자를 하나만 다룬다(고객 가용 별도 입력 없음).
- **여행사 할당도 기준값 + 조정**(S1-A3, 구 S2-A4 흡수): 여행사 × 자산별 **기준 할당 + 적용 시작일**(A3-M4)을 상속하고, 특정 날짜만은 **재고 조정에서 대상 = 여행사 할당**으로 건다. 그날 여행사 할당 = 기준 할당 + 그 여행사 할당 조정 합.
  - 할당을 늘려 **할당 합 > 총 보유**가 되는 날이 생기면 **저장 차단**(이미 초과인 날을 줄이는 변경은 허용). 보유가 줄어 넘으면 **경고 후 허용**, 그날 고객 가용 0.
  - 여행사 예약 마감(**이용일 D-3**)이 지나면 안 팔린 할당은 **고객 가용으로 자동 반환**. 삭제된 여행사의 할당은 삭제일부터 0.
- **재고 화면의 표시 기준**: 달력 셀 숫자 = **`잔여 / 고객 가용`**, 색상은 **잔여** 기준(여유·임박·마감(0)·초과).
- **휴무/블랙아웃**: **매장 전역** 플래그다(전 자산 공통). 수량 값은 **보존한 채 판매만 차단**하며, 특정 자산 하나만 못 쓰는 날은 휴무가 아니라 **재고 조정으로 수량 0**을 만들어 표현한다.
- **재고 초과 허용**: 재고를 그날 예약 수보다 낮게 내리면 **경고 후 저장을 허용**하고(실제 파손은 사실이므로), 그 날짜에 **'초과' 표시** + **대시보드(S1-A1) 알림**이 남는다. 고객앱은 이미 0이라 신규 예약은 유입되지 않으며 관리자가 개별 연락·취소로 해소한다.
- **예약 가능 기간**: 고객 = 오늘 +1일 ~ +3개월 / 여행사 = 오늘 +3일 ~ +3개월. '오늘'은 **일본 기준**.
- **가격**: 고객가 / 여행사가 이원화. 여행사가는 고객앱 미노출.
- **결제**: PG 미사용. 고객은 무통장 입금 후 관리자 **수동 확인**. 24시간 내 미입금 시 강제취소 가능.
- **고객 예약 상태 흐름**: 접수 → 완료(입금확인) → 취소요청 → 취소.
- **예약 구성 단위**: **1 예약번호 = N 항목**(상품 × 옵션 × 이용일 조합). 항목마다 상품·옵션·이용일·수량·금액이 다를 수 있으므로, 예약을 단일 상품·단일 이용일로 표기하지 않는다. 목록 카드는 **대표 상품명 + '외 N건'**.
- **부분취소**: 항목 단위 취소 가능. **완료(입금확인) 이후**부터 허용하고, **입금대기** 상태에서는 **전체 취소만**(입금액 변동·재안내 방지). 부분취소는 **별도 상태값·탭을 만들지 않고 '부분취소' 뱃지**로 표시하며, 예약 상태는 **유효 항목 기준**으로 유지한다. 바우처에서 취소 항목은 회색·취소 뱃지로 남기고 합계는 유효 항목만 반영.
- **여행사 예약 상태**: 예약 = 즉시 완료 / 취소 = 즉시(입금 흐름 없음).
- **취소 수수료**: 이용일 기준 차등 요율(관리자 세팅). **항목마다 이용일이 다르므로 항목별로 각각 산정해 합산**한다(예약 단위 일괄 산정 불가). 환불 이체는 관리자 수동 처리, 취소 확정 시 **해당 항목·날짜의 재고만** 복원.
- **여행사 취소 마감**: 기본 D-3, 관리자가 유연 조정 가능. 취소 시 재고 즉시 복원.
- **인보이스**: 매월 1일 전월 기준 발행, KRW·세금 라인 없음, 정산은 수동 확인.
- **여권 영문명**: 가입이 아닌 **예약 시점**에 확보. 회원정보에서 변경 가능.
- **알림**: 문의 답변 등 → 카카오 알림톡(현재는 알림 인터페이스, 실발송 이연).
- **콘텐츠(랜딩·서비스 소개·FAQ)**: 관리자 CMS-lite에서 편집, 고객은 읽기 전용.
